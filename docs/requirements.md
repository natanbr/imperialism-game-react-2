milestone; a changed requirement gets a new id and the old row says `replaced by FR-###`.

Status values: `planned`, `tested` (test exists and is green), `replaced`, `dropped`.

## M1 Headless core

Written 2026-11-03 at the start of M1 part A (engine). Part B (store and UI wiring) adds its
own rows after FR-017.

| Id | Requirement | Status |
|---|---|---|
| FR-001 | The game engine lives in `src/app/engine/` and imports no React, Zustand, Next, `@/store` or `@/components`, and uses no DOM globals or `Math.random`/`Date.now`; an ESLint rule enforces this. | tested |
| FR-002 | `GameState` carries `seed: number`. WHEN a turn resolves THEN every random draw comes from an RNG derived only from the seed and the turn number, so no random state lives outside `GameState`. | tested |
| FR-003 | Every action the UI offers today is an `Order`, a union discriminated on `kind`. Every order names its `nationId` and its worker or tile ids explicitly; no order starts more than one worker. | tested |
| FR-004 | WHEN an order is validated THEN `validateOrder(state, order)` returns `{ ok: true }` or `{ ok: false, reason }` with a reason from a fixed string-literal union, and never changes the state. | tested |
| FR-005 | WHEN a valid order is applied THEN `applyOrder` performs its immediate effects (move the worker, start the job, charge the treasury or warehouse). WHEN the order is invalid THEN it returns the same state object unchanged. | tested |
| FR-006 | WHEN a worker order names a worker that is working THEN it is refused with `worker-busy`; WHEN the worker already moved this turn THEN it is refused with `worker-moved`. This holds for move, move-and-start, start and engineer rail-on-move. | tested |
| FR-007 | Move-and-start is all or nothing: WHEN the job cannot start on the target THEN neither the move nor the charge happens and the reason is returned (`insufficient-funds` when money is short); there is no retry with an unlimited treasury. | tested |
| FR-008 | WHEN an engineer moves onto an adjacent tile to build rail THEN the order is refused unless the engineer is available and unmoved, the tile is a valid rail site with no unfinished construction job (`tile-occupied`), and the nation can pay. | tested |
| FR-009 | WHEN a port is started (chosen or picked automatically) THEN the tile must have a river or an adjacent ocean tile, otherwise `invalid-site`. | tested |
| FR-010 | Transport orders: WHEN allocations are set THEN every amount is a non-negative number; WHEN capacity is bought THEN one coal and one iron ore per unit are taken from the warehouse and the increase is queued for next turn, all or nothing; WHEN a queued increase is reduced THEN the materials are refunded. | replaced by FR-039 (freight cars cost lumber, steel and labour) |
| FR-011 | `resolveTurn(state, ordersByNation, seed)` returns `{ state, events }`. It is the only place where the turn's orders are applied (nations in state order), the queued transport capacity is applied, all systems run, workers are reset and the turn and year advance. A rejected order produces an `order-rejected` event with its reason. | tested |
| FR-012 | Every turn system has the shape `(state, ctx) => state`, where `ctx` carries the RNG, the turn's accepted orders and an events sink. | tested |
| FR-013 | No engine function mutates its input: WHEN the input state is deep-frozen THEN orders, systems (the rail network helpers included) and `resolveTurn` run without error and the input stays deep-equal to its snapshot. | tested |
| FR-014 | Replay determinism: WHEN the same initial state and the same order list run for 10 turns twice THEN the final states are deep-equal. | tested |
| FR-015 | Two nations from `mockNation.ts` play 20 turns headlessly, each through the same order API, driven by a scripted player. Both treasuries change and after every turn no worker is on two tiles, no treasury is negative and no job is orphaned. | tested |
| FR-016 | A scripted player is a function `(state, nationId) => Order[]` in `engine/ai/scriptedPlayer.ts`; it only proposes orders that `validateOrder` accepts in sequence. | tested |
| FR-017 | Until part B wires the store to orders, the store's worker actions (`workerHelpers`, `handleEngineerMovement`, `startEngineerWork`, the worker start functions) are thin adapters over `validateOrder`/`applyOrder`, so FR-006 to FR-009 hold in the running app. | replaced by FR-022, FR-023 (part B removed the adapters) |

| Id | Requirement | Status |
|---|---|---|
| FR-027 | Calendar: a new game starts on turn 1 in Spring 1815. Each turn is one season (Spring, Summer, Fall, Winter, in that order) and the year advances after Winter. `seasonOf(turn)` gives the season. | tested |
| FR-028 | Job durations come from one table (`definisions/workerDurations.ts`): prospecting 1 turn, rail 1, depot 3, port 3, fort 3, every development level 3 for every worker type. `constants/gameConstants.ts` holds no durations. [NEEDS CLARIFICATION] gaps.md A4: level-ups other than the miner's and the forester's first are not documented; default 3. | tested |
| FR-029 | Job costs, charged when the job is ordered: development to level 1, 2, 3 costs $100, $1,000, $5,000; depot $2,000; port $3,000; fort level 1 $5,000; rail by the terrain of the tile it is built on: $100 on farm, plains, desert and other flat land, $150 on tundra and either forest, $200 on hills, $300 on swamp. [NEEDS CLARIFICATION] gaps.md B3: rail on mountains is not documented, default $300; gaps.md A4: prospecting is not documented, default $100. | tested |
| FR-030 | Construction sites (refused with `invalid-site`): rail only where `canBuildRailAt` allows (also for `startConstruction`), and not on hills (barren or fertile) before Compound Steam Engine, swamp before Iron Railroad Bridge, mountains before Dynamite; a depot not on a tile with a depot and not next to a depot, a port or the capital (gaps.md F6: "not adjacent"), and not on hills before Compound Steam Engine; a port not where a port already is and not on hills or mountains; a fort only where the fort level is 0 (the capital counts as level 1; levels 2 and 3 need technology). A technology counts when `technologyState.technologies` holds it with `purchased: true`. | tested |
| FR-031 | WHEN a job ordered this turn is cancelled THEN its cost is refunded (rules 03: orders can be cancelled until End Turn and the cash comes back). WHEN a job ordered on an earlier turn is cancelled THEN it stops without a refund. | tested |
| FR-032 | A finished job leaves its tile in the resolution that finishes it: the worker is available next turn, another job may start on the tile next turn, and the completion event is the only trace. Jobs carry no `completed` or `completedOnTurn` flags. The map's "done" mark reads the last turn's completion events. | tested |
| FR-033 | Every nation has the production buildings textile mill, lumber mill, steel mill (mills, start capacity 2), clothing factory, furniture factory, metal works (factories, start capacity 1), refinery (a mill, capacity 0 until built, only after Oil Drilling) and food processing (no capacity limit). Standing production orders are kept between turns, except food processing, whose orders are cleared after each production phase. [NEEDS CLARIFICATION] gaps.md A6: a new game starts with the six mills and factories built (the Introductory and Easy rule and the gaps.md fallback). | tested |
| FR-034 | Recipes per output unit (rules 05 section 2): fabric 2 cotton-or-wool (any mix); clothing 2 fabric; lumber or paper 2 timber (one shared capacity); furniture 2 lumber; steel 1 coal + 1 iron ore; hardware or armaments 2 steel (one shared capacity); fuel 2 oil; each takes 2 labour. Canned food is made in batches of 2 cans from 2 grain + 1 fruit + 1 livestock-or-fish + 2 labour. [NEEDS CLARIFICATION] gaps.md B6: a single can for one odd labour unit is not modelled; canned food orders are even. | tested |
| FR-035 | Labour: a nation's labour is untrained x1 + trained x2 + expert x4, not counting sick workers and workers in training. Standing production orders and the freight cars ordered this turn (2 each) commit labour. `labourOf(nation)` returns `{ total, committed, free }`. | tested |
| FR-036 | `setProduction { nationId, building, output?, amount }` sets the building's standing order for that output (default: the building's first output). Refused: an unknown or unbuilt building or an output it does not make (`invalid-target`); an amount that is not a non-negative integer, or odd for canned food (`invalid-amount`); an amount above the building's capacity less its other output's order (`limit-reached`); an amount whose inputs exceed the warehouse stock (`insufficient-resources`) or whose labour, with all other standing orders, exceeds the nation's labour (`insufficient-labour`). Lowering an order is always accepted. Applying it changes nothing but the order. | tested |
| FR-037 | Production phase: WHEN a turn resolves THEN, for each nation, the freight cars ordered are built first and then each building in a fixed order produces min(order, capacity, what the warehouse inputs allow, what the remaining labour allows). Inputs and labour are taken as each runs; all outputs reach the warehouse after every building ran, so a product made this turn is not an input this turn. Each product made gives a `goods-produced` event. No warehouse stock ever becomes negative. | tested |
| FR-038 | `expandBuilding { nationId, building }` raises a capped building one step: mills and the refinery 0, 2, 4, 8, 16, 24, then +8; factories 0, 1, 2, 4, 8, 12, then +4 (0 to the first step is the first construction). It costs 1 lumber + 1 steel per capacity point added, taken when ordered, all or nothing (`insufficient-resources`), no labour. The new capacity counts from next turn (after this turn's production phase) and gives a `building-expanded` event. Food processing, and the refinery before Oil Drilling, are refused (`invalid-target`). | tested |
| FR-039 | Transport orders: allocations are non-negative numbers (as FR-010). `changeTransportCapacity` with `delta > 0` orders freight cars: 1 lumber + 1 steel per car taken from the warehouse at once and 2 labour per car committed, all or nothing (`insufficient-resources`, `insufficient-labour`); a negative delta gives back part of this turn's order with a refund. The cars are built in the production phase, count for this turn's shipping, and give a `freight-cars-built` event; a car the labour no longer covers is not built and its materials are refunded. | tested |
| FR-040 | Food: WHEN a turn resolves, after shipments reach the warehouse, THEN every industrial worker eats 1 food. Workers are fed experts first, then trained, then untrained; worker slot i in that order prefers grain, fruit, grain, livestock-or-fish, repeating. First every slot eats its preferred raw food, then the unfed eat canned food, then any other raw food (the worker is sick: no labour next turn), and a worker with nothing starves and leaves the workforce. A `workers-fed` event reports how many ate well, fell sick and starved. [NEEDS CLARIFICATION] gaps.md B7: who goes hungry first is not documented; default the untrained (then trained, then experts) take the sick and starved places, and sickness lasts until the next meal. | tested |
| FR-041 | Training: `trainWorkers { nationId, from, delta }` trains untrained to trained for $100 + 1 paper each, or trained to expert for $1,000 + 2 paper each, paid when ordered (a negative delta cancels this turn's trainees with a refund). Refused: experts (`invalid-target`), more trainees than healthy workers of that grade (`invalid-amount`), not enough cash (`insufficient-funds`) or paper (`insufficient-resources`), or a trainee's labour that is not free (`insufficient-labour`). A trainee gives no labour this turn and is promoted at the end of the production phase (`workers-trained` event). | replaced by FR-058 (training needs 1 free labour, not the trainee's) |
| FR-042 | Migration: `recruitWorkers { nationId, delta }` takes 1 canned food + 1 clothing + 1 furniture per worker when ordered, no cash and no labour (a negative delta gives back this turn's order). The new untrained workers join after this turn's meal and eat from the next turn on (`workers-recruited` event). At most max(1, floor(provinces / 4)) per turn (`limit-reached`). [NEEDS CLARIFICATION] gaps.md B8: the cap is unconfirmed and the remake has no provinces yet, so at least 1. | tested |
| FR-043 | The engine owns the world a new game needs: `engine/newGame.ts` imports nothing from `@/testing`. A new game is the 40x40 default map with one nation that has $10,000, 4 untrained, 2 trained and 1 expert worker, 15 freight cars, the six mills and factories built and a start warehouse (grain 20; fruit, livestock, timber, cotton, wool, coal, iron ore, lumber, steel and canned food 10 each). Test fixtures stay in `src/app/testing`. [NEEDS CLARIFICATION] gaps.md A6: the start warehouse is not documented. | tested |
| FR-044 | Acceptance: in a headless game, grain from a farm next to the capital reaches the warehouse through transport and, after a food processing order, ends up as canned food; the same game without the farm's grain makes no canned food. | tested |
| FR-045 | Two scripted nations play 20 turns headlessly and both produce goods and feed their workers; the FR-015 invariants hold after every turn, and no warehouse stock or worker count is ever negative. | tested |

## M3 Money and score

Written 2026-11-03 at the start of M3 part A (engine). Sources: `docs/rules/06` (market, holds),
`docs/rules/01` (game length, score), `docs/rules/05` section 4 (training, migration); open numbers
reference `docs/rules/gaps.md` and the decision cards Q10 to Q15 in `docs/journal.md`. The market is
one per game and every nation trades on it, so M4's second nation needs no new market. Part B (UI)
adds its own rows after these.

| Id | Requirement | Status |
|---|---|---|
| FR-060 | World market: the game SHALL have one market (`GameState.market`) shared by every nation, holding one world price per tradeable commodity in whole dollars, this turn's sell offers and buy bids by nation, and the purchases on their way by nation. Tradeable: every warehouse commodity except raw food (grain, fruit, livestock, fish), gold and gems (rules 06 section 2). A new game and the test worlds SHALL start at the start prices: resources $100 except horses $300, materials $300 except canned food $100, goods $900 (rules 06 section 4). `marketOf(state)` returns the market, or the start market for a hand-built state without one. [NEEDS CLARIFICATION] gaps.md A1, decision Q13: the exact start prices are not documented. | planned |
| FR-061 | Selling: `sellCommodity { nationId, commodity, amount }` SHALL set this turn's sell offer of the commodity to `amount` units. The units leave the warehouse when ordered; a lower amount returns the difference (0 cancels), so an offer and its cancel leave the state as it was. Refused: a commodity that is not tradeable or not an own key (`invalid-target`), an amount that is not a whole number of at least 0 (`invalid-amount`), a commodity the nation bids on this turn (`invalid-target`; rules 06: no offer and bid on the same commodity), more units than the warehouse holds (`insufficient-resources`), or more units traded this turn than the nation's holds (`limit-reached`, FR-063). Lowering an offer SHALL always be accepted. | planned |
| FR-062 | Buying: `buyCommodity { nationId, commodity, amount }` SHALL set this turn's buy bid of the commodity to `amount` units, paid when ordered at this turn's world price (prices change only in the trade phase, so the price paid is the deal price); a lower amount refunds the difference (0 cancels). Refused: a commodity that is not tradeable or not an own key (`invalid-target`), a bad amount (`invalid-amount`), a commodity the nation offers this turn (`invalid-target`), a fifth commodity bid on in one turn (`limit-reached`; rules 06: at most 4 buy bids), more units traded than the holds (`limit-reached`), or not enough cash (`insufficient-funds`). Lowering a bid SHALL always be accepted. | planned |
| FR-063 | Trade capacity: every unit sold or bought SHALL take one cargo hold for the turn, and a nation SHALL trade at most `merchantMarine.holds` units a turn, sales and purchases together (rules 06 section 3; a new game has 4 holds). v1 has no Shipyard, so the holds do not grow. `tradeCapacityOf(state, nationId)` SHALL return `{ holds, used, free }`. [NEEDS CLARIFICATION] decision Q14: whether v1 keeps this limit. | planned |
| FR-064 | Trade phase: WHEN a turn resolves THEN the trade phase (after diplomacy, before production) SHALL pay every nation's sales at this turn's world price (a `goods-sold` event per commodity with amount, price and income), record its purchases (a `goods-bought` event with amount, price and cost) and clear the turn's offers and bids. The bought units SHALL reach the warehouse with the transported goods, after production and before the workers' meal, so production can use them from the next turn (rules 06 section 1: usable next turn). Trade orders last one turn. [NEEDS CLARIFICATION] decision Q15: in the rules they persist until changed. | planned |
| FR-065 | Price drift: WHEN the trade phase has settled the deals THEN every tradeable commodity's price SHALL move by a random drift between -3% and +3% (from the turn RNG, one draw per commodity every turn, in a fixed commodity order) plus a push of +0.5% per unit bought and -0.5% per unit sold by all nations together, the push capped at 3% either way; the result is rounded to whole dollars and kept between 50% and 250% of the commodity's start price. The same seed and orders SHALL give the same prices. [NEEDS CLARIFICATION] gaps.md A1, decision Q13: the original price formula is not documented. | planned |
| FR-066 | Recruitment and training cost money: training SHALL keep costing cash and paper as in FR-058 (unchanged, not duplicated). Recruiting a migrant SHALL keep costing 1 canned food + 1 clothing + 1 furniture and no cash (FR-042, rules 05 section 4); all three are tradeable, so a nation without them SHALL be able to buy them on the world market in one turn and recruit on the next. [NEEDS CLARIFICATION] decision Q10: a cash fee per migrant is not in the rules; default none. | planned |
| FR-067 | Score: `scoreOf(state, nationId)` SHALL be a pure query of the nation's score: treasury points floor(treasury / 100), industry points 10 per capacity point of its mills, factories and refinery (food processing has no capacity; capacity ordered this turn counts from the next turn), and development points 10 per resource level on its own tiles (a level-2 farm gives 20; a level-0 or undiscovered resource gives 0), returned with the parts and their total. `scoreTable(state)` SHALL list every nation's score, highest total first, ties in nation order. [NEEDS CLARIFICATION] gaps.md A7, decision Q11: the original weights are not documented. | planned |
| FR-068 | Game over: a game SHALL last `turnLimit` turns, set by `newGame({ seed, turnLimit })` with default 40 (Spring 1815 to Winter 1824, just before the first Council meeting in Spring 1825); the test worlds also last 40; `turnLimitOf(state)` reads it (40 for a hand-built state without one). WHEN the turn numbered `turnLimit` resolves THEN, after the clock advances, the state SHALL hold `gameOver = { turn, year, scores }` (the last turn played, its year and the final `scoreTable`), and a `game-over` event SHALL follow the `turn-ended` event.
